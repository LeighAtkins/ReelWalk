# ADR 0014: Production on EKS and RDS, kept small

Status: accepted (2026-10-07)

## Context

ADR 0005 ran the chart on kind until there was a reason to pay for a
cluster. There is one now: the share links, the Instagram OAuth callback and
the videos Instagram fetches all need a public HTTPS address, and the user
chose EKS plus RDS over a single VM.

## Decision

`infra/terraform` now also creates:

- A VPC in two zones. **Nodes sit in public subnets with public addresses
  and there is no NAT gateway**: a NAT gateway costs more per month than the
  database, and the nodes are protected by their security group, not by
  being unreachable. The database subnets are private.
- An EKS cluster (Kubernetes 1.34) with one managed node group of
  `t3.xlarge`, min 1 max 3. One node carries the web app, a render worker,
  ingress-nginx and cert-manager.
- **EKS Pod Identity** instead of IRSA or static keys: the `reelwalk`
  ServiceAccount is associated with a role carrying the same `reelwalk-app`
  policy the local IAM user has. The SDK's default credential chain picks it
  up; the cluster Secret holds no S3 keys.
- RDS Postgres 16 on `db.t4g.micro`, encrypted, 7-day backups, reachable only
  from the node security group. The password is generated by Terraform and
  copied into the cluster Secret by `infra/eks/deploy.sh`.
- The budget alert moves to $300 a month. Expected run rate: EKS control
  plane ~$73, one node ~$120, NLB ~$17, RDS ~$13, plus storage and traffic.

`infra/eks/deploy.sh` installs ingress-nginx (behind an NLB) and cert-manager
with a Let's Encrypt issuer, writes `reelwalk-secrets` from Terraform outputs
and `.env`, and installs the chart with `values-aws.yaml` and the image tag
from `values-gitops.yaml` (ECR repositories, same tags CI pushes). DNS at
Cloudflare points `reelwalking.com` at the load balancer.

## Consequences

- Deploys are `infra/eks/deploy.sh <sha>` from a workstation for now. Argo
  CD on the cluster, tracking `values-aws.yaml`, is the next step and needs
  only the kind install script generalised.
- Scanner findings about public node subnets, the public API endpoint,
  control-plane logging and RDS extras are accepted as cost decisions in
  `.trivyignore.yaml`.
- Destroying the cluster is `terraform destroy -target module.eks` plus the
  RDS instance; the bucket, queues and ECR stay.
