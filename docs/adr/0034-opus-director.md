# 0034 — Opus directs AI-assisted reels inside the editor

The existing Ask tool receives a timeline description. It cannot judge video continuity from that metadata, write generation proposals with stored approvals, or distinguish a real playback review from looking at a thumbnail. Separate creative scripts also hide the decisions from the studio.

Add **Ask → Direct and review with Opus**. This workflow requires the configured Anthropic Opus provider; it never falls back to another model. The user supplies a brief and may select three candidate takes or reference photos. The browser samples source frames using its normal owned/signed library URLs, prioritizing candidates and AI clips, up to ten sheets. AI/candidate videos have up to forty samples spanning the source; real footage samples the used windows. Failed decoding or CORS is an error, never a silent thumbnail substitute. No audio or final composited render is supplied.

Opus returns separate scale, camera continuity, presenter continuity and property identity checks with evidence; an uncertain or failed check cannot accompany a ready verdict. The server additionally refuses a ready verdict without sampled evidence for each reviewed AI source. This is sampled-frame criticism, not a guarantee of correct physics, lip sync, typography contrast or seamless playback. It must not claim to have watched or heard the final film.

The result includes normal editor operations and up to three Veo proposals. Opus writes the exact prompt, duration and first/last owned frame references. The review, model, usage, baseline, proposed timeline, evidence timestamps/hashes and proposals are saved in `AiEdit.plan`. No schema migration is needed. Applying a proposal is an explicit undoable editor step and is refused if the baseline timeline changed. Captions are shown before applying. Existing voiced footage remains reusable, while new app Veo generations remain silent under ADR 0033's pricing.

Each Veo proposal shows its credit quote and requires an approval click. The server reads the stored Opus proposal, not a browser-supplied replacement prompt. Only this server path bypasses the usual prompt embellishment; browser generation input cannot request that bypass. A deterministic UUID per edit/proposal reuses the existing credit-reservation idempotency path, including when a worker wake response is lost. It retains ownership, storage, workspace credit, concurrency and global spend limits. A retry requires Opus to propose a new take and another explicit generation approval. Completed takes are refreshed for another Opus review; they are not automatically appended or published.

Director model requests also have a stable caller UUID and payload hash in `AiJob`. Identical submissions resume the job, changed payloads cannot reuse its identity, and ambiguous provider submissions are never automatically repeated. Pending/failed requests and completed reviews are accessible from the sheet. Like the existing Ask background path, model work can be interrupted by a server restart; the saved pending state is conservative, not permission to resubmit a paid request.

The endpoint bounds streamed request bodies to 8 MB, decoded image input to 6 MB and sharp input dimensions. Every media ID and timestamp is checked against studio-accessible media before use. Images are decoded and converted to JPEG; no browser-provided URL or storage key is fetched by the server. Sampled sheets go only to the configured model; the database keeps timestamps and hashes rather than embedding base64 images.

Validation: core/service/route tests cover source ownership and bounds, invalid source types, separate proposal/application, model selection, missing evidence, failed/uncertain checks, unchanged exact prompts, approval identity reuse, cross-studio request identities and bounded uploads. A local browser harness uses the actual sheet, source decoder and property video with mocked model/generation endpoints; it must be described as a UI test, not a live Opus verdict. Production use and further creative generation wait for the reviewed implementation to be deployed.
