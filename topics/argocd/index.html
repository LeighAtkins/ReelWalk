Argo CD

GitOpsによるデプロイ

アルゴシーディーRuns locally with a stand-in

Gitの内容(ないよう)に、クラスターを合わせ続ける、GitOpsのツールです。

A GitOps tool that keeps the cluster matching what is in Git.

ローカルで検証(けんしょう) Running on local kind only: Argo CD v3.5.3 is installed, the Application auto-syncs main with prune and selfHeal, and a merge to main was seen rolling new GHCR images into the cluster. Never run against EKS or in production.

How to explain it

  1. Argo CD(アルゴシーディー)は、クラスターの中で動くデプロイツールです。

    Argo CD is a deployment tool that runs inside the cluster.

  2. Gitにあるマニフェストを、正しい状態として扱(あつか)います。

    It treats the manifests in Git as the desired state.

  3. クラスターとの差分(さぶん)を見つけると、自動で同期(どうき)します。

    When it finds drift from the cluster, it syncs automatically.

  4. CIがクラスターに入れるのではなく、プル型です。

    It is pull-based, rather than CI pushing into the cluster.

  5. ReelWalkでは、Applicationのマニフェストを書きました。

    For ReelWalk I wrote the Application manifest.

  6. Helmチャートとvalues-kind.yamlを、参照(さんしょう)する設定です。

    It points at the Helm chart and values-kind.yaml.

  7. pruneとselfHealを、有効(ゆうこう)にしています。

    prune and selfHeal are enabled.

  8. イメージのタグは、CIがGitに書き込(こ)みます。

    CI writes the image tag into Git.

  9. ローカルのkindにインストールして、動かしています。

    It is installed and running on local kind.

Why ReelWalk uses it

  1. Gitが唯一(ゆいいつ)の正解になり、変更の履歴(りれき)が残ります。

    Git becomes the single source of truth, with a change history.

  2. ロールバックは、Gitのコミットを戻すだけです。

    Rolling back is just reverting a commit.

  3. CIに、クラスターの認証情報を渡さなくて済(す)みます。

    CI does not need cluster credentials.

  4. 一方で、Argo CD自体(じたい)の運用が増えます。

    On the other hand, Argo CD itself must be operated.

Interview questions

GitOpsとは、何ですか？What is GitOps?

  1. Gitを、デプロイの唯一の正解にするやり方です。

    It makes Git the single source of truth for deployment.

  2. クラスターの状態を、Gitのマニフェストに合わせます。

    The cluster is kept matching the manifests in Git.

  3. 手で変えた設定は、自動で元(もと)に戻ります。

    Manual changes are reverted automatically.

  4. 変更は全部プルリクエストなので、レビューと履歴が残ります。

    Every change is a pull request, so it is reviewed and recorded.

Contrast push (CI runs kubectl/helm with cluster credentials) and pull (an agent in the cluster watches Git).

Argo CD(アルゴシーディー)は、実際に使っていますか？Are you actually using Argo CD?

  1. はい、ローカルのkindで使っています。

    Yes, on local kind.

  2. mainにマージすると、新しいイメージが自動でデプロイされます。

    When I merge to main, the new images are deployed automatically.

  3. ただ、本番での運用経験はまだありません。

    But I have no production experience with it yet.

  4. マイグレーションのJobには、sync-waveを付けています。

    The migration Job has a sync-wave annotation.

  5. Deploymentより先に、Jobが終わるようにするためです。

    So the Job finishes before the Deployments sync.

Scope first (local kind, not production), then one detail (sync-wave -1) that shows you understand ordering.

ロールバックは、どうしますか？How do you roll back?

  1. Gitで、前のコミットにrevertします。

    Revert to the previous commit in Git.

  2. Argo CDがそれを検知(けんち)して、前の状態に戻します。

    Argo CD detects it and restores the previous state.

  3. ただし、DBのマイグレーションは自動では戻りません。

    But database migrations do not roll back automatically.

  4. なので、マイグレーションは後方互換(こうほうごかん)を保(たも)つことが大事です。

    So migrations must stay backward compatible.

The database is the hard part of any rollback; mentioning expand-and-contract migrations is a plus.

Where it lives in ReelWalk

  • infra/argocd/application.yaml

    Application tracking main, path infra/helm/reelwalk with values-kind.yaml and values-gitops.yaml, automated prune and selfHeal.

  • infra/argocd/install.sh

    Installs Argo CD v3.5.3 into kind with server-side apply, then applies the Application.

  • infra/helm/reelwalk/values-gitops.yaml

    Image repository and tag, rewritten by the CI release job on every merge to main.

  • infra/helm/reelwalk/templates/migrate-job.yaml

    argocd.argoproj.io/sync-wave: "-1" so the migration completes before the Deployments sync.
