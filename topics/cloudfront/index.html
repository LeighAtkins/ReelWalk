CloudFront

動画の配信(はいしん)（CDN）

クラウドフロントBuilt and running

完成した動画を、近くのエッジから速く届けるCDNです。

A CDN that delivers finished videos quickly from a nearby edge.

実装済(じっそうず)み Built: the production distribution (imported into Terraform, origin access control so only CloudFront reads the bucket) serves finished MP4s at dh5xvp6apljoh.cloudfront.net; the app uses it when CLOUDFRONT_BASE_URL is set and presigned S3 URLs otherwise. No signed URLs: share links are the access control.

How to explain it

  1. CloudFrontは、AWSのCDNです。

    CloudFront is AWS's CDN.

  2. 世界中のエッジから、動画を速く届けられます。

    It can deliver video fast from edges around the world.

  3. 今は、S3の署名付(しょめいつ)きURLで動画を返しています。

    Today the app returns videos as S3 presigned URLs.

  4. 環境変数を設定すれば、CloudFrontのURLに切り替わります。

    Setting an environment variable switches to CloudFront URLs.

  5. 本番では、OACでS3を非公開(ひこうかい)のままにする設計です。

    In production the design keeps S3 private by using OAC.

  6. 見る人の制限は、署名付きURLか署名付きCookieでします。

    Who can watch is controlled with signed URLs or signed cookies.

  7. 本番(ほんばん)では、OACまでは実装(じっそう)していて、署名付きURLはまだです。

    In production OAC is in place; signed URLs are not yet.

Why ReelWalk uses it

  1. 動画は大きいので、S3から直接だと遅くて高くなります。

    Videos are large, so serving straight from S3 is slower and costlier.

  2. 出力のキーはジョブごとに変わらないので、長くキャッシュできます。

    Each job's output key never changes, so it can be cached for a long time.

  3. その代わり、署名の鍵やOACなど、設定が増えます。

    The trade-off is more setup: signing keys, OAC and so on.

Interview questions

完成した動画は、どうやって届けていますか？How do finished videos reach the user?

  1. 今は、S3の署名付(しょめいつ)きURLを返しています。

    Right now the app returns an S3 presigned URL.

  2. ローカルでは、S3の代わりにMinIOです。

    Locally MinIO stands in for S3.

  3. 本番(ほんばん)では、CloudFrontが完成(かんせい)した動画を配信(はいしん)しています。

    In production CloudFront delivers the finished videos.

  4. 共有(きょうゆう)リンクのページも、そのURLを使っています。

    The share-link page uses those URLs too.

CloudFront is real: the distribution was imported into Terraform with origin access control. What is not done is signed URLs; the share link is the access control today.

OACと署名付きURLは、何が違いますか？How do OAC and signed URLs differ?

  1. OACは、CloudFrontからS3への権限です。

    OAC is CloudFront's permission to read S3.

  2. S3を非公開にしたまま、CloudFrontだけが読めます。

    S3 stays private and only CloudFront can read it.

  3. 署名付きURLは、見る人への制限です。

    A signed URL limits the viewer.

  4. 誰が、いつまで見られるかを決めます。

    It decides who can watch, and until when.

They protect different hops: OAC is CloudFront to S3, signed URLs are viewer to CloudFront. Production would use both.

キャッシュの更新は、どうしますか？How would you refresh the cache?

  1. 出力のキーは、ジョブIDから作っています。

    The output key is built from the job ID.

  2. 成功したジョブの動画は、もう変わりません。

    A succeeded job's video never changes.

  3. 新しく書き出すと、新しいジョブとキーになります。

    A new export means a new job and a new key.

  4. なので、無効化(むこうか)はほとんど要りません。

    So invalidation is almost never needed.
