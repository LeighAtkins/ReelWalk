Prisma

型付(かたつ)きのDBアクセス

プリズマBuilt and running

DBの定義と型付(かたつ)きクライアントを、Webとワーカーで共有(きょうゆう)します。

The DB definition and a typed client are shared by the web app and the worker.

実装済(じっそうず)み Built: Prisma 7 with @prisma/adapter-pg, seven committed migrations, a migrate Job in the Helm chart (kind, and EKS for a day), and a one-off Fargate task that applies them in production.

How to explain it

  1. Prisma(プリズマ)は、TypeScript向けのORMです。

    Prisma is an ORM for TypeScript.

  2. schema.prismaに、モデルを書きます。

    You write the models in schema.prisma.

  3. そこから、型付(かたつ)きのクライアントが生成(せいせい)されます。

    A typed client is generated from it.

  4. スキーマとマイグレーションは、packages/dbにあります。

    The schema and migrations live in packages/db.

  5. Webとワーカーが、同じクライアントを使っています。

    The web app and the worker use the same client.

  6. マイグレーションは、SQLファイルとしてコミットします。

    Migrations are committed as SQL files.

  7. クラスタでは、KubernetesのJobで適用(てきよう)します。

    On the cluster, a Kubernetes Job applies them.

  8. アプリが更新される前に、prisma migrate deployが走ります。

    prisma migrate deploy runs before the app is updated.

Why ReelWalk uses it

  1. 一番の理由は、Webとワーカーで型を共有できることです。

    The main reason is sharing types between web and worker.

  2. 最初はasyncpgで生(なま)のSQLを書いていましたが、型が共有できませんでした。

    The first version used raw SQL with asyncpg, but types couldn't be shared.

  3. トレードオフは、generateを先に実行しないと型エラーになることです。

    The trade-off is that you get type errors unless generate runs first.

  4. Prisma 7では、ドライバーアダプターも必要になりました。

    Prisma 7 also requires a driver adapter.

Interview questions

マイグレーションは、どう運用していますか？How do you run migrations?

  1. 開発中は、prisma migrate devでSQLを作ってコミットします。

    During development, prisma migrate dev creates the SQL and I commit it.

  2. クラスタでは、HelmのJobがmigrate deployを実行します。

    On the cluster, a Helm Job runs migrate deploy.

  3. Argo CDでは、このJobが先に終わるようにしています。

    With Argo CD, this Job is made to finish first.

  4. Jobの名前にハッシュを入れて、リリースごとに作り直します。

    The Job name includes a hash, so each release creates a new one.

  5. これはkindで検証(けんしょう)しました。

    I verified this on kind.

Mention the Job pod template is immutable, which is why the name carries a hash. Say kind, not EKS.

Prismaを使ってみて、困ったことはありますか？Any problems using Prisma?

  1. クライアントがリポジトリの中に生成されることです。

    The client is generated into the repository tree.

  2. generateを忘れると、型チェックもテストも失敗します。

    If you forget generate, typecheck and tests both fail.

  3. なので、Turborepoで最初に実行されるようにしました。

    So I made Turborepo run it first.

  4. もう一つは、Next.jsの開発中に接続(せつぞく)が増えることです。

    Another was connections piling up during Next.js development.

  5. クライアントをglobalThisに置いて、一つだけにしています。

    I keep the client on globalThis so there's only one.

Concrete pain + concrete fix. Both fixes are visible in turbo.json and packages/db/src/index.ts.

Where it lives in ReelWalk

  • packages/db/prisma/schema.prisma

    All models: Workspace, User, Reel, MediaAsset, Tour, RenderJob, RenderOutput.

  • packages/db/prisma/migrations

    Committed SQL migrations applied with migrate deploy.

  • packages/db/src/index.ts

    The shared client with the pg adapter, kept on globalThis in dev.

  • infra/helm/reelwalk/templates/migrate-job.yaml

    The one-shot migrate Job (Argo CD sync-wave -1, name hashed per release).
