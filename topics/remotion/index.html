Remotion

Reactで動画を作る

リモーションBuilt and running

一つのReactコンポーネントで、プレビューと書(か)き出(だ)しの両方(りょうほう)を描(えが)きます。

One React component draws both the live preview and the exported video.

実装済(じっそうず)み Built: the Player preview and worker renders to MP4 both work locally and in the Playwright e2e run; ADR 0006 records the decision.

ExplainWhyWordsInterviewIn the repoWatch

How to explain it

  1. Remotion(リモーション)は、Reactで動画を作るライブラリです。

    Remotion is a library for making video with React.

  2. フレーム番号から、その瞬間(しゅんかん)の画面を描(えが)きます。

    From a frame number, it draws the picture for that moment.

  3. ReelWalkでは、ReelCompositionがリールを描きます。

    In ReelWalk, ReelComposition draws a reel.

  4. エディターでは、@remotion/playerでプレビューします。

    In the editor, it's previewed with @remotion/player.

  5. 書き出しでは、ワーカーが同じコンポーネントをレンダリングします。

    On export, the worker renders the same component.

  6. 中ではヘッドレスChromeとffmpegが動いています。

    Inside, headless Chrome and ffmpeg do the work.

  7. だから、スマホで見たものと動画がずれません。

    So the video matches what you saw on the phone.

  8. 違(ちが)いは、動画のデコード方法だけです。

    The only difference is how video is decoded.

Why ReelWalk uses it

  1. プレビューと書き出しを別々に作ると、だんだんずれていきます。

    If preview and export are built separately, they drift apart.

  2. 一つのコンポーネントなら、機能を一回書くだけで済みます。

    With one component, each feature is written once.

  3. トレードオフは、ワーカーのイメージが約1.5GBと大きいことです。

    The trade-off is a large worker image, about 1.5 GB.

  4. それと、4人以上の会社では有料(ゆうりょう)ライセンスが必要です。

    Also, companies of four or more people need a paid licence.

Interview questions

なぜスマホの中で書(か)き出(だ)さないんですか？Why not export on the phone itself?

  1. サーバー代はかかりませんが、中くらいのスマホだと遅いです。

    It costs nothing on the server, but it's slow on mid-range phones.

  2. 画面がロックされると、止まってしまいます。

    It stops when the screen locks.

  3. それに、失敗した時に再試行(さいしこう)するジョブが残りません。

    And when it fails, there's no job left to retry.

  4. なので、書き出しはサーバーのワーカーでやっています。

    So exports run on a worker on the server.

Show you weighed the cheaper option. The older desktop editor (apps/editor) does in-browser export, so you know both.

プレビューと書き出しで、違いはありますか？Are there differences between preview and export?

  1. 動画のデコードだけ違います。

    Only video decoding differs.

  2. プレビューは普通(ふつう)のvideo要素(ようそ)で、スマホのハードウェアを使います。

    The preview uses a plain video element with the phone's hardware decoder.

  3. ワーカーは@remotion/mediaで、WebCodecsを使います。

    The worker uses @remotion/media, which uses WebCodecs.

  4. 測(はか)ったら、OffthreadVideoの約2倍速(ばいそく)でした。

    When I measured it, it was about twice as fast as OffthreadVideo.

  5. フォントやフィルターは同じなので、見た目は一致(いっち)します。

    Fonts and filters are the same, so the look matches.

"I measured it" is strong. Keep the number modest and say it was a local measurement.

レンダリングを速くするには、どうしますか？How would you make rendering faster?

  1. 時間のほとんどは、動画のデコードです。

    Most of the time goes into decoding video.

  2. 一つのレンダリングの中では、RENDER_CONCURRENCYで並列度(へいれつど)を上げます。

    Within one render, RENDER_CONCURRENCY raises the parallelism.

  3. 全体(ぜんたい)としては、ワーカーのPodを増やしてスケールアウトします。

    Overall, I scale out by adding worker pods.

  4. キューの長さでスケールするKEDAは、次の課題(かだい)です。

    Scaling on queue depth with KEDA is the next step.

Separate scale-up (concurrency per render) from scale-out (more pods). KEDA is planned, not built.
