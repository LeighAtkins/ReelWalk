Server Actions

サーバー側(がわ)の更新処理

サーバーアクションBuilt and running

更新はすべてServer Actionsで、入口(いりぐち)で検証(けんしょう)と権限(けんげん)を確認します。

Every update is a Server Action that checks input and permissions at the entry point.

実装済(じっそうず)み Built: createReel, saveReel (revision check), saveCaption, createUpload, confirmUpload, exportReel and retryRenderJob are real; there is no login yet, so the workspace comes from a seeded demo user.

ExplainWhyWordsInterviewIn the repoWatch

How to explain it

  1. Server Actionsは、サーバーの関数をブラウザから呼べる仕組(しく)みです。

    Server Actions let the browser call a function on the server.

  2. ReelWalkでは、データの更新はすべてServer Actionsです。

    In ReelWalk, every data change is a Server Action.

  3. リールの作成(さくせい)、保存、アップロード、書(か)き出(だ)しなどです。

    Creating a reel, saving, uploading, exporting, and so on.

  4. 入口(いりぐち)では、必ずzodで入力を検証(けんしょう)します。

    At the entry point, input is always validated with zod.

  5. クエリには、必ずworkspaceIdを条件に入れます。

    Every query includes workspaceId as a condition.

  6. 保存には、リビジョン番号を使っています。

    Saving uses a revision number.

  7. 古いリビジョンからの保存は、拒否(きょひ)されます。

    A save from an old revision is rejected.

  8. 別のタブの変更を、黙(だま)って上書(うわが)きしないためです。

    So that another tab's changes are never silently overwritten.

Why ReelWalk uses it

  1. フォームやfetch用のAPIを、別に作らなくて済みます。

    I don't need a separate API for forms or fetch calls.

  2. 引数(ひきすう)と戻(もど)り値の型が、そのままクライアントにつながります。

    Argument and return types flow straight through to the client.

  3. ただ、リクエストボディのサイズに制限(せいげん)があります。

    But there is a limit on the request body size.

  4. なので、大きな動画はServer Actionsを通さず、S3に直接送ります。

    So large videos skip Server Actions and go straight to S3.

Interview questions

リビジョンチェックは、どう実装(じっそう)しましたか？How did you implement the revision check?

  1. ブラウザは、最後に見たリビジョンを一緒に送ります。

    The browser sends the last revision it saw along with the save.

  2. サーバーは、updateManyのwhereにそのリビジョンを入れます。

    The server puts that revision in the where clause of updateMany.

  3. 成功したら、リビジョンを1つ増やします。

    On success, the revision is incremented by one.

  4. 更新件数(こうしんけんすう)が0なら、別のタブが先に保存したということです。

    If zero rows changed, another tab saved first.

  5. その時は上書きせず、再読(さいよ)み込みをお願いします。

    Then it doesn't overwrite, and asks the user to reload.

Name it: 楽観的ロック (optimistic locking). Mention it's one SQL statement, no read-then-write, no explicit lock.

Server Actionsのセキュリティで、気をつけていることは？What do you watch out for with Server Actions security?

  1. Server Actionsは、実質(じっしつ)的に公開(こうかい)されたエンドポイントです。

    A Server Action is effectively a public endpoint.

  2. なので、入力は必ずzodで検証(けんしょう)します。

    So input is always validated with zod.

  3. クエリは全部、ワークスペースで絞(しぼ)り込みます。

    Every query is scoped to the workspace.

  4. 保存の時は、使っているメディアが同じワークスペースのものかも確認します。

    On save I also check the media used belongs to the same workspace.

  5. ただ、ログインはまだなく、デモユーザーで動いています。

    But there's no login yet; it runs as a demo user.

Being upfront that auth is missing (and that it's isolated in one function) reads as maturity, not weakness.

書(か)き出(だ)しの時、サーバーでは何をしていますか？What does the server do on export?

  1. まず、Instagramのルールをサーバーでもう一度チェックします。

    First it re-checks the Instagram rules on the server.

  2. 次に、その時点のタイムラインをジョブに保存します。

    Next it saves the timeline as of that moment into the job.

  3. 後で編集しても、書き出す動画は変わりません。

    Later edits don't change the video being exported.

  4. 同じトランザクションで、キューへのメッセージもDBに書きます。

    In the same transaction, it also writes the queue message to the database.

  5. コミットの後で、そのメッセージをキューに送ります。

    After the commit, it sends that message to the queue.

Freezing the payload makes retries deterministic. Link to the queue and idempotency topics if they dig in.

Where it lives in ReelWalk

  • apps/web/app/actions.ts

    Every Server Action; see saveReel for the revision check and retryRenderJob for a conditional retry.

  • apps/web/components/editor/use-autosave.ts

    Calls saveReel 700 ms after an edit with the last revision it saw.

  • apps/web/lib/workspace.ts

    getCurrentUser: the one place to swap in real auth later.

  • packages/core/src/instagram.ts

    Instagram rules, re-checked on the server inside exportReel.
