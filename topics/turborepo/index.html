Turborepo

モノレポのタスク実行

ターボレポBuilt and running

モノレポのタスクを、依存関係(いぞんかんけい)の順にキャッシュ付きで実行します。

Runs the monorepo's tasks in dependency order, with caching.

実装済(じっそうず)み Built: `pnpm typecheck/test/build` run through turbo locally and in GitHub Actions; caching is local only (no remote cache), and the Dockerfiles do not use turbo prune.

ExplainWhyWordsInterviewIn the repoWatch

How to explain it

  1. Turborepo(ターボレポ)は、モノレポ用のタスクランナーです。

    Turborepo is a task runner for monorepos.

  2. pnpmのワークスペースで、appsとpackagesを管理しています。

    apps and packages are managed as a pnpm workspace.

  3. typecheck、test、buildを、依存関係(いぞんかんけい)の順に実行します。

    It runs typecheck, test and build in dependency order.

  4. 結果はキャッシュされるので、変更がなければすぐ終わります。

    Results are cached, so with no changes it finishes instantly.

  5. 大事なのは、db:generateを最初に走らせることです。

    The key point is running db:generate first.

  6. Prismaのクライアントがないと、型チェックが通らないからです。

    Without the Prisma client, the type check fails.

  7. turbo.jsonのdependsOnで、この順番を書いています。

    turbo.json's dependsOn encodes that order.

Why ReelWalk uses it

  1. Webとワーカーが、core、db、renderのパッケージを共有しているからです。

    Because web and worker share the core, db and render packages.

  2. 順番を手で管理するのは、ミスのもとです。

    Managing the order by hand invites mistakes.

  3. トレードオフは、設定を間違えると古いキャッシュが使われることです。

    The trade-off is that a wrong config can serve a stale cache.

  4. db:generateにはinputsを書いて、スキーマが変わった時だけ再生成(さいせいせい)します。

    db:generate declares its inputs, so it regenerates only when the schema changes.

Interview questions

turbo.jsonの「^」は、何を意味(いみ)しますか？What does the ^ in turbo.json mean?

  1. 依存(いぞん)しているパッケージの、同じタスクという意味です。

    It means the same task in the packages this one depends on.

  2. ^db:generateなら、依存先(いぞんさき)のdb:generateを先に実行します。

    ^db:generate runs db:generate in dependencies first.

  3. webの型チェックの前に、dbのgenerateが走ります。

    Before web's type check, db's generate runs.

  4. ^がなければ、同じパッケージの中のタスクです。

    Without ^, it refers to a task in the same package.

A small syntax question that checks you actually wrote the config. Have turbo.json in your head.

Turborepoを入れて、何が良くなりましたか？What improved after adding Turborepo?

  1. コマンド一つで、全部のパッケージをチェックできます。

    One command checks every package.

  2. Prismaのgenerate忘(わす)れが、なくなりました。

    Forgetting Prisma generate stopped happening.

  3. 変更のないパッケージは、キャッシュで飛ばされます。

    Unchanged packages are skipped thanks to the cache.

Lead with the concrete problem it solved (generate ordering), not just "it's faster".

リモートキャッシュは使っていますか？Do you use remote caching?

  1. 今は使っていません。キャッシュはローカルだけです。

    Not now. The cache is local only.

  2. CIでは、pnpmのストアとDockerのレイヤーをキャッシュしています。

    In CI, I cache the pnpm store and Docker layers.

  3. チームで使うなら、リモートキャッシュを入れると思います。

    For a team, I'd add a remote cache.

  4. CIの時間が、かなり短くなるはずです。

    It should cut CI time considerably.

Honest scope, plus what you'd do on a team. Craftsman uses Turborepo, so expect follow-ups on caching.

Where it lives in ReelWalk

  • turbo.json

    The task graph: typecheck and test depend on db:generate and ^db:generate.

  • pnpm-workspace.yaml

    Workspace members: apps/*, packages/*, e2e.

  • package.json

    Root scripts that call turbo run typecheck/test/build.

  • .github/workflows/ci.yml

    CI runs pnpm lint, typecheck and test, which go through turbo.
